## Profi core

- **RTC в `avr.vhd`: память часов перезаписывается каждый такт.** В процессе записи
  RTC-регистров ветка `else` пишет в RAM `rtcr_a`/`rtcr_d` (последний пакет от AVR)
  на каждом такте `CLK`. Если CPU пишет регистр по тому же адресу, следующий такт
  затирает его старым значением от AVR. Писать в RAM только по приходу пакета
  `CMD_RTC` (строб `spi_do_valid`). Нашлось при разборе WIP Gemini, октябрь 2026.

- **RTC в `avr.vhd`: повторные пакеты в AVR на одну запись CPU.** Автомат очереди
  из `rtc_wr_ack` сразу уходит в `idle`. Пока `RTC_WR_N` ещё 0, условие
  `RTC_WR_N = '0' and RTC_CS = '1'` снова срабатывает и в очередь уходит ещё один
  такой же пакет. Ждать в `rtc_wr_ack` окончания `RTC_WR_N`. Нашлось при разборе WIP Gemini.

- **Заменить T80 на z80-silicone.** Взять ядро из проекта `karabas-go-core-tsconf`.
  Сейчас T80a работает на гейтированном `clk_cpu` и использует оба фронта `CLK_n`.
  Его стробы (`M1_n`, `WR_n_i`, `MREQ`) используются в ядре как клоки.
  При замене надо проверить DivMMC automap, порты и contention.
  Нужна проверка на железе.

- **Стробы CPU в роли клоков.**
  Эти триггеры защёлкиваются по стробам CPU, и TimeQuest их не анализирует:
  - `mapcond` / `automap`: по спаду `MREQ`, это DivMMC;
  - `port_xxfe_reg`: по фронту `WR`, это бордюр и бипер;
  - `fd_port`: по фронту `M1`;
  - `buf_md` в `memory.vhd`.

  Их надо перевести на `clk_bus` или описать в SDC.
  Поведение завязано на точные моменты стробов Z80, поэтому нужна проверка на железе.
  Это можно сделать вместе с заменой CPU.

- **Оставшиеся защёлки**, которые Quartus сообщает как latch:
  - `N_CE1..3` в `memory.vhd`: выбор микросхем SRAM;
  - `status_reg` в `serial_mouse.vhd`.

  Затрагивают обмен с SRAM и мышью, поэтому нужна проверка на железе.

- **ep4ce6 заполнен на 99%.** Путь turbosound → tda1543 в домене 28 МГц проходит
  с минимальным запасом и может провалиться при другой раскладке.

## Репозиторий и инфраструктура

- **Переводы строк в `software/profi`.** Часть файлов (`fatfs/*`,
  `net-tools/src/pqdos/browser/player/player.asm` и др.) лежит в git с CRLF, а
  `.gitattributes` требует LF. Поэтому в каждом свежем checkout или worktree они
  сразу показываются изменёнными. Сделать `git add --renormalize software/` отдельным PR.

- **Срок действия `QUARTUS_DIST_TOKEN`.** Fine-grained токен, через который CI скачивает
  Quartus из приватного `andykarpov/quartus13-dist`, имеет срок действия. Когда он
  истечёт, сборки FPGA в CI упадут на шаге «Download Quartus tarball»: выпустить
  новый токен (Contents: Read-only, только этот репозиторий) и обновить секрет.
