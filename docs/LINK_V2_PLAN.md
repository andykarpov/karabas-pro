# Линк AVR ↔ FPGA v2: план

Статус: план утверждён владельцем 2026-11-19. Ф0..Ф3 сделаны (без проверки на железе), дальше Ф4.
Открыто перед слиянием в master: hold EP3C10 (раздел Ф3), README релиза.

Цель — закрыть технический долг: переделать обмен AVR ↔ FPGA по образцу линка v2 Karabas Go
(karabas-go-firmware `docs/link_v2.md`, karabas-go-modules `kg_l2_link.v`): один пакет на chip
select вместо 3-байтных кадров и без холостых NOP. OSD остаётся текстовым: шрифты и растр в AVR
не влезут.

## Как ведётся работа

- Вся работа идёт в ветке `link-v2` (от `master` 8fbc791). Туда же идёт исправление INT в турбо.
  В `master` всё попадает одним PR и выходит одним релизом.
- Обратной совместимости нет: новая прошивка AVR работает только с новой прошивкой FPGA.
  AVR и FPGA обновляются вместе, в README релиза об этом сказано отдельно.
- CI (`build-fpga.yml`, `build-avr.yml`, `sim.yml`) запускается только для `master`. В первом
  же коммите с кодом добавить `link-v2` в их триггеры или собирать локально (CLAUDE.md, «Сборка»).
- Проверка на железе ограничена: плата EP4CE10 есть, а VGA-монитора и PS/2-клавиатуры сейчас
  нет. Поэтому:
  - всё, что можно, доказывается в симуляции (стенды ниже обязательны, а не «по желанию»);
  - на плате проверяется то, что видно без монитора и клавиатуры: старт AVR и FPGA, светодиоды,
    обмен по линку (см. «Отладка без монитора»);
  - картинка, клавиатура, мышь и джойстик проверяются, когда появятся монитор и клавиатура.
    До этого PR в `master` помечается «Needs hardware», пункты записываются в `BACKLOG.md`.

## Что есть сейчас (master 8fbc791)

- Кадр — 3 байта (cmd, addr, data), CS опускается на каждый кадр. FPGA отвечает в тех же байтах
  из очереди на 512 записей (`rtl/avr/queue.vhd`, dcfifo).
- В каждом проходе главного цикла AVR шлёт 10 кадров клавиатуры (матрица 41 бит и переключатели,
  `keyboard_transmit()`) и кадр джойстика, даже если ничего не изменилось.
- Символ OSD — 4 кадра (X, Y, char, attr), 12 байт. Полный экран 32 × 26 — около 10 КБ,
  примерно 0,1 с.
- SCK 1 МГц (`hal_spi_init()`: fosc/16), в SDC `AVR_SCK` объявлен на 1 МГц. Предел AVR — 8 МГц.
- FPGA держит очередь наполовину заполненной кадрами LED (`led_req`), записи CPU в RTC встают
  за ними.
- Сканкод (кадры 07 / 08) передаётся, но `KB_SCANCODE` в топе не подключён (`open`).
- EP4CE6: 6198 / 6272 LE. Блок `avr:U15` занимает 550 LE: очередь 138, `spi_slave` 107,
  остальное 306. Блочной памяти занято 24 %.
- AVR: flash 23012 / 32768 байт, RAM 515 / 2048 байт.

## Физический уровень

Между AVR и FPGA только 4 провода через U8 (TXB0104, на всех ревизиях A..E): MOSI, SCK, CS, MISO.
Линии INT нет, свободных выводов у ATmega328P нет. Решение владельца:

- состояние FPGA (биты «есть что прочитать» и светодиоды) идёт в байте 1 ответа **каждого**
  пакета;
- когда передавать нечего, AVR шлёт пакет опроса из 2 байт;
- MISO в роли INT при поднятом CS не используется (он выведен и на разъём ISP).

SPI mode 0, старший бит первым. Частота: 1 МГц в Ф2, затем 4 и 8 МГц (Ф3).

## Протокол

Протокол описан в [AVR_LINK_V2.md](AVR_LINK_V2.md) (первая вычитка владельца 2026-11-19, её правки:
каждый пункт меню — свой байт `SYS SETVAL`, только при изменении и без повторов; `HID JOY` со
всеми кнопками в раскладке Go; `HID PS2` зарезервирован под сырые сканкоды; модуль на Verilog).
Цели: SYS (`POLL`, `STATUS`, `INIT`, `SETVAL`), HID (`MATRIX`, `MOUSE`, `JOY`, `PS2`), OSD
(`WRITE` с автоинкрементом), RTC (`SET`, `GET`).

Матрица остаётся на стороне AVR (решение владельца). Причины: `hid_parser` Go на EP4CE6 стоит
466 LE (пробный синтез), а свободно около 74 LE; скорости линку он не прибавляет, если матрица
уходит одним пакетом при изменении; хоткеи, меню OSD и маппинг джойстика на клавиши всё равно
на AVR.

## Фазы

Каждая фаза — один или несколько коммитов в `link-v2`. Перед следующей фазой предыдущая собрана
и проверена, как описано у неё.

### Ф0. INT кадра в турбо (из karabas-go-core-profi 9179e88)

- Сейчас в турбо INT укорочен под частоту CPU (`video/pentagon_video.vhd`, ветки `TURBO`;
  `video/profi_video.vhd`, `pcpm_h_int_on_turbo`). При `fdd_wait` CPU падает до 3,5 МГц, а INT
  остаётся турбо-длины, и CPU может его пропустить. В турбо для Classic берётся тайминг INT
  Pentagon (`SCREEN_MODE` не смотрится).
- Правка: INT длиной как на 3,5 МГц во всех режимах, снимается по INTA (как `vid_int_ack` в Go).
- Проверка: GHDL-стенд положения и длины INT в каждом турбо и экранном режиме, снятие по INTA,
  нет второго INT за кадр; мутации. Сборка трёх чипов, тайминги против `master`.
- Needs hardware: игры и демо в турбо, часы ROMain.
- Сделано: INT снимается по INTA в `video.vhd` только пока CPU быстрее 3,5 МГц (`cpu_fast` в
  топе, условие из `clk_cpu_en`); на 3,5 МГц INT тот же, что был (у Go снятие по INTA всегда).
  `sim/run_int.sh`: 12 прогонов по 0 ошибок, 6 мутаций пойманы; scandoubler совпал с эталоном;
  LE: EP4CE6 6198 (как в master), EP4CE10 8458 (−47), EP3C10 8475 (−61); отрицательного slack нет.

### Ф1. Спецификация

- `docs/AVR_LINK_V2.md` (только по-русски, как остальные документы `docs/`): коды целей и команд, биты статуса, порядок старта, частоты. Вычитывает
  владелец, дальше код пишется по ней.

### Ф2. Рефакторинг AVR без изменения поведения

- Модули зовут API линка (`link_matrix`, `link_ctrl`, `link_mouse`, `link_joy`, `link_osd_*`,
  `link_rtc_*`) вместо `spi_send()`. На проводе всё ещё v1 байт в байт.
- Проверка: хост-тест (gcc, подменённый SPI) записывает поток байт для набора сценариев
  (старт, клавиши, мышь, отрисовка меню, RTC) до и после правки, потоки совпадают.
- Сделано: `include/link.h` (API, индексы `SETVAL`, биты `JOY` по спецификации),
  `src/link_v1.c` (вся раскладка в кадры v1, в том числе таблица «индекс `SETVAL` → биты»,
  которую потом повторит FPGA); матрица в `keyboard.c` — только 41 клавиша, пункты меню и
  управление идут через `link_setval()`, джойстик — 16 бит в раскладке Go. Стенд
  `firmware/src/avr/host_test/run.sh`: два прогона сценария (стёртая EEPROM и сохранённые
  настройки, 413733 и 407260 кадров) байт в байт совпадают с master, 9 мутаций линка пойманы.
  AVR: flash 23774 байт (+714, таблица v1, уйдёт в Ф3), RAM 487 (−29).

### Ф3. Новый линк (FPGA и AVR вместе)

- FPGA: модуль линка на Verilog на транспорте `kg_l2_link` (из karabas-go-modules) с целями
  SYS / HID / OSD / RTC. Порты в сторону ядра прежние, `karabas_pro.vhd` почти не
  меняется. Очередь dcfifo уходит, остаётся маленький FIFO записей RTC.
- AVR: драйвер v2 под API из Ф2.
- Проверка:
  - стенд эквивалентности по событиям: старый `avr.vhd` с кадрами v1 (GHDL) и новый модуль с
    пакетами v2 (iverilog) при одинаковых логических событиях дают одинаковые `KB`, `SOFT_SW` / переключатели, мышь,
    содержимое RTC RAM, записи в VRAM OSD; мутации показывают, что стенд ловит ошибки;
  - `sim/tb_boot.vhd` с VHDL-заглушкой модуля линка; `tb_rtc` уходит в стенд iverilog;
  - сборка трёх чипов (EP4CE6 должен влезть), тайминги против `master`.
- Needs hardware: старт, светодиоды, отладочный вывод линка (см. ниже); клавиатура, мышь,
  джойстик и OSD — когда будут монитор и клавиатура.
- Сделано:
  - FPGA: `rtl/avr/avr_link.v` (транспорт `kg_l2_link` master 40184bd), `rtl/avr/avr.vhd` —
    VHDL-адаптер с `message_rom`; `overlay.vhd` пишет видеопамять OSD прямо с линка; ушли
    `spi_slave`, `queue`, `rtc` (IP); SDC: `AVR_SCK` 8 МГц.
  - AVR: `src/link_v2.c` (только при изменении, прогоны OSD / RTC в одном пакете,
    `link_service()` в конце прохода, `link_flush()` перед `joystick_handle()`), `link_v1.c` ушёл.
    Flash 23738 байт, RAM 510.
  - Ошибки, которые нашли стенды: `GET` забирал запись из FIFO по предвыборке, до байта
    значения (стенд модуля, обрыв пакета); прогон OSD длиннее 1024 байт портил адрес (счётчик
    позиции транспорта 10 бит; сравнение со старым модулем: очистка экрана одним пакетом).
  - `sim/run_avr_link.sh`: стенд модуля 0 ошибок в 6 сочетаниях клоков; оба сценария хост-стенда
    на старом и новом модуле одинаковы (сценарий a: 89 состояний на 124319 проходах, 35019 записей
    OSD, 256 регистров RTC; b: 87 состояний, 35070 записей); фильтр кадров v1 сверен с
    нефильтрованным потоком на первых 40000 проходах; мутации модуля и прошивки пойманы.
  - LE: EP4CE6 6189 (master 6198; `avr` 517 вместо 550, `overlay` 132 вместо 186), EP4CE10 8337
    (8505), EP3C10 8352 (8536). Slow-модель без отрицательного slack на всех трёх.
  - **Открыто: EP3C10, fast-модель, hold −0,023 нс** на `WAIT_C[1] → WAIT_C[0]` (счётчик на спаде
    `clk_bus`, к линку не относится). У EP3C10 клок `clk_bus` выходит из логической ячейки
    (`clk_ctrl` U3), часть нагрузок фиттер подключает в обход глобальной сети («intentional clock
    skew»: 21 в master, 34 здесь), перекос между битами счётчика ~1 нс. В Ф0 худший hold на этом
    чипе был +0,083 нс (`fdd_cnt`, тоже на спаде): запас около нуля от сборки к сборке. До
    слияния в master надо решить (см. `BACKLOG.md`).

### Ф4. Частота SCK

- 1 → 4 → 8 МГц: `SPR` / `SPI2X` в `hal_spi_init()`, `create_clock` для `AVR_SCK` в SDC,
  тайминги. Останавливаемся на той частоте, где линк работает без ошибок на плате.
- Проверка: тайминги; на плате — счётчик ошибок линка из отладочного вывода.

### Ф5. OSD и иконки

- FPGA: регистр между `icons` и `overlay` (сейчас `RGB_O` иконок идёт в мультиплексор OSD
  комбинационно); явный строб записи VRAM вместо сравнения с `last_osd_command`.
  Проверка: `sim/run_scandoubler.sh`, тайминги.
- AVR: отрисовка OSD строками, popup, шапка. Что именно поправить в меню и иконках — список
  владельца.

## Отладка без монитора

Чтобы проверить линк на плате без VGA и PS/2, нужен отладочный вывод AVR: выводы `AVR_TX` /
`AVR_RX` (PD1 / PD0) выведены на разъём. Через USB-UART адаптер AVR может печатать результат
`SYS STATUS`, номер сборки FPGA, счётчики пакетов и ошибок. Сделать в Ф3 под флагом сборки.
Адаптер у владельца есть, но для подключения надо разбирать корпус, поэтому вывод нужен такой,
чтобы хватило одного-двух подключений. UART в AVR раньше отключали ради экономии flash; сейчас
место есть (около 9,7 КБ свободно), его можно вернуть.
