# Линк AVR ↔ FPGA v2: спецификация

Статус: черновик на вычитку (ветка `link-v2`, Ф1 плана [LINK_V2_PLAN.md](LINK_V2_PLAN.md)).
Пока владелец его не вычитал, код по нему не пишется. Номера в скобках вида `(avr.vhd)`
показывают, где это сейчас в v1.

Образец — линк v2 Karabas Go (karabas-go-firmware `docs/link_v2.md`): один пакет на chip select,
маленькие цели в FPGA. С Go по проводам не совместим и не должен быть: у Pro нет линии INT, нет
загрузки ROM и образов через MCU, OSD текстовый.

Совместимости с v1 нет: прошивка AVR v2 работает только с FPGA v2 и наоборот. AVR и FPGA
обновляются вместе.

## 1. Физический уровень

| Сигнал | Вывод AVR | Вывод FPGA | Направление |
|---|---|---|---|
| `SCK` | PB5 | `AVR_SCK` (PIN_89) | AVR → FPGA |
| `MOSI` | PB3 | `AVR_MOSI` (PIN_90) | AVR → FPGA |
| `MISO` | PB4 (подтяжка) | `AVR_MISO` (PIN_87) | FPGA → AVR, FPGA ведёт его только при CS = 0 |
| `CS` | PD7 | `AVR_NCS` (PIN_88) | AVR → FPGA, активный 0, подтяжка 10k к VCC |

Все четыре линии идут через U8 (TXB0104) на всех ревизиях A..E. Других линий между AVR и FPGA
нет, поэтому нет и INT: FPGA сообщает о себе байтом статуса в каждом пакете (раздел 3).

- SPI mode 0 (CPOL 0, CPHA 0), старший бит первым, байты по 8 бит.
- Частота SCK: 1 МГц (fosc/16, как в v1) до Ф4 плана, затем 4 МГц (fosc/4) и 8 МГц
  (fosc/2, SPI2X), если пройдут на плате. FPGA должна работать на любой из них.
- Паузы между байтами внутри пакета могут быть любыми (AVR передаёт по байту с опросом SPIF).
- Между пакетами CS держится в 1 не меньше **1 мкс**: по нему FPGA заканчивает пакет.

## 2. Пакет

```
CS     ‾‾\_____________________________________________________/‾‾
MOSI       T     C     P0   ...  Pn-1   00    00   ...  00
MISO       00    S     x    ...  x      x     D0   ...  Dm-1
```

- `T` — цель (раздел 4), `C` — команда, `P0..Pn-1` — параметры.
- `S` — байт статуса FPGA (раздел 3). Он есть в **каждом** пакете, в ответ на байт `C`. Байт
  ответа на `T` всегда 0.
- У команды, которая возвращает данные, после последнего параметра идёт **байт разворота**
  (AVR шлёт 0, ответ не определён), затем данные `D0..Dm-1` (AVR шлёт 0).
- Спад CS начинает новый пакет, подъём заканчивает. Недопринятый пакет отбрасывается: команды,
  которые применяют данные целиком (`CTRL`, `MATRIX`, `MOUSE`), применяют их только на последнем
  байте.
- Неизвестные `T` и `C` игнорируются до подъёма CS. Лишние байты после параметров игнорируются,
  чтение за концом данных даёт 0.
- Многобайтные числа — little-endian.

Самый короткий пакет — `00 00` (`SYS POLL`): только статус.

## 3. Байт статуса

| Бит | Имя | Значение |
|---|---|---|
| 0 | `INIT_REQ` | 1 — FPGA ждёт инициализации: после включения (сброс `areset`) и до `SYS INIT` |
| 1 | `RTC_PEND` | 1 — в FIFO есть записи CPU в RTC, читать `RTC GET` |
| 2 | — | всегда 0 |
| 3 | — | всегда 0 |
| 4 | `LED1` | состояние LED1 от FPGA (было `CMD_LED_WRITE` бит 0) |
| 5 | `LED2` | LED2 (бит 1) |
| 6 | `LED1_OWR` | FPGA управляет LED1 (бит 2) |
| 7 | `LED2_OWR` | FPGA управляет LED2 (бит 3) |

Биты 2 и 3 всегда 0, поэтому `FF` (FPGA не сконфигурирована, MISO висит на подтяжке AVR) не
бывает правильным статусом. AVR считает его «нет FPGA».

`INIT_REQ` ставится только по `areset` (включение, переконфигурация FPGA, потеря захвата PLL), а
не по сбросу CPU: `CTRL RESET` от AVR его не трогает.

Пакетов LED больше нет: AVR берёт светодиоды из статуса любого пакета.

## 4. Цели и команды

`→` — параметры от AVR, `←` — данные от FPGA (после байта разворота).

### 4.1 SYS (`T = 00`)

| C | Имя | → | ← | Примечание |
|---|---|---|---|---|
| `00` | `POLL` | | | Только статус |
| `01` | `STATUS` | | 12 байт | `'K' 'P'`, версия `02`, конфигурация, 8 символов номера сборки FPGA (ASCII). Пока ROM не загружена из flash (`LOADER_DONE = 0`), все байты 0 |
| `02` | `INIT` | | | Инициализация закончена: снимает `INIT_REQ`, с этого момента FPGA ставит записи CPU в RTC в FIFO |
| `03` | `CTRL` | 4 байта | | Управление и переключатели (таблица ниже), применяются на последнем байте |

Байт конфигурации `STATUS` (как ответ на `CMD_INIT` в v1): биты 7..6 `max_turbo`, биты 5..0
`CFG(5 downto 0)` (ревизия платы, тип ЦАП: `docs/karabas_pro_cfg.txt`).

Номер сборки — 8 байт из `message_rom` (в v1 их запрашивали восемью кадрами `CMD_BUILD`).

Биты `CTRL` (в v1 — биты 41..79 матрицы клавиатуры, кадры `CMD_KBD` 06..0A):

| Байт | Бит | Имя | Порт `avr.vhd` | Что это |
|---|---|---|---|---|
| 0 | 0 | `RESET` | `RESET` | Сброс машины |
| 0 | 1 | `MAGICK` | `MAGICK` | Magic / NMI |
| 0 | 2 | `WAIT` | `WAIT_CPU` | Пауза CPU |
| 0 | 3..4 | `TURBO` | `TURBO(1 downto 0)` | Турбо-режим |
| 0 | 5 | `KB_MODE` | `KB_MODE` | Раскладка: Profi XT / Spectrum |
| 0 | 6 | `OSD_OVERLAY` | `OSD_OVERLAY` | Меню OSD открыто |
| 0 | 7 | `OSD_POPUP` | `OSD_POPUP` | Всплывающее окно OSD |
| 1 | 0..7 | `SW1..SW8` | `SOFT_SW(1 to 8)` | SW1 видео VGA/RGB, SW2 60 Гц, SW3..SW4 банк ROM, SW5 TurboFDC, SW6 Covox, SW7 ABC, SW8 тип PSG |
| 2 | 0..1 | `SW9..SW10` | `SOFT_SW(9 to 10)` | SW9 моно, SW10 Swap FDD |
| 2 | 2 | `JOY_TYPE` | `JOY_TYPE` | 0 Atari, 1 Sega |
| 2 | 3..4 | `SCREEN_MODE` | `SCREEN_MODE(1 downto 0)` | 00 Pentagon, 01 Classic |
| 2 | 5..7 | `JOY_MODE` | `JOY_MODE(2 downto 0)` | Kempston, Sinclair 1, Sinclair 2, Cursor, QAOP |
| 3 | 0 | `DIVMMC` | `DIVMMC_EN` | |
| 3 | 1 | `NEMOIDE` | `NEMOIDE_EN` | |
| 3 | 2 | `PLUS3E` | `PLUS3E` | Банк ROM +3e |
| 3 | 3..7 | — | | 0, резерв (например, монитор ленты) |

Из v1 не переносятся: `IS_UP` и биты сканкода (бит 44, 48..56; `KB_SCANCODE` в топе не
подключён), `LOADED` (`kb_loaded` никуда не идёт).

### 4.2 HID (`T = 01`)

| C | Имя | → | Примечание |
|---|---|---|---|
| `01` | `MATRIX` | 6 байт | Биты 0..39 — клавиши матрицы ZX (`ZX_K_*` 0..39, как в v1), бит 40 — пятый бит Profi (`ZX_K_BIT6`), биты 41..47 — 0. Применяется на последнем байте целиком |
| `02` | `MOUSE` | 3 байта | `dx`, `dy` (знаковые), байт `Z`: биты 3..0 колесо (знаковое), 4 левая, 5 правая, 6 средняя, 7 — 0. Одно событие мыши на пакет: строб на последнем байте (в v1 — переключение бита 7) |
| `03` | `JOY` | 1 байт | Тот же байт, что `CMD_JOY` в v1 (`avr.vhd`: 0 fire, 1 fire2, 2 up, 3 down, 4 left, 5 right, 6 A, 7 B) |

### 4.3 OSD (`T = 02`)

Экран OSD тот же: 32 × 26 знакомест, в видеопамяти слово на знакоместо (символ, атрибут).

| C | Имя | → | Примечание |
|---|---|---|---|
| `01` | `WRITE` | адрес (2 байта), затем (символ, атрибут) × n | Адрес = y × 32 + x (10 бит, y 0..25). После каждого атрибута адрес увеличивается на 1, после 1023 идёт 0. Пишется сколько угодно знакомест подряд, хоть весь экран одним пакетом |

Атрибут как в v1 (`overlay.vhd`): биты 7..5 цвет символа R G B, бит 4 его яркость, биты 3..1
цвет фона R G B, бит 0 яркость фона; младшая тетрада `0001` — мигание.

Видимость OSD задают `CTRL OSD_OVERLAY` и `OSD_POPUP`, как сейчас.

### 4.4 RTC (`T = 03`)

| C | Имя | → | ← | Примечание |
|---|---|---|---|---|
| `01` | `SET` | первый регистр, значения | | Регистр first + k = значение k, адрес по кругу (8 бит). Запись CPU в тот же момент имеет приоритет, значение AVR пишется следующим тактом (как в v1, `tb_rtc`) |
| `02` | `GET` | | регистр, значение | Одна запись CPU из FIFO; чтение значения забирает её. Пустой FIFO: `00 00` |

FIFO записей CPU: 256 записей в блочной памяти (в v1 общая очередь на 512). Записи ставятся
только после `SYS INIT`. Переполнение: новая запись теряется. `RTC_PEND = 1`, пока FIFO не пуст.

## 5. Работа AVR

### 5.1 Старт

1. Опрос `SYS STATUS` раз в 10 мс, пока не придёт `'K' 'P' 02` (без ограничения по времени:
   FPGA может конфигурироваться и грузить ROM долго). Светодиоды до ответа — как сейчас до
   `CMD_INIT`.
2. Конфигурация и номер сборки из `STATUS` идут в меню (`zxosd_set_fpga_cfg`,
   `zxosd_set_fpga_build_num`), `max_turbo` — в `keyboard_set_max_turbo`.
3. `CTRL` с текущими переключателями, `MATRIX` пустая, `JOY`.
4. `RTC SET 00` со всеми 256 регистрами одним пакетом (как `rtc_send_all`; в v1 его слали дважды).
5. `SYS INIT`.
6. Сброс машины: `CTRL` с `RESET = 1`, через 100 мс с `RESET = 0` (`keyboard_do_reset`).
7. Заставка OSD (`zxosd_show_boot_popup`).

Если в статусе любого пакета появился `INIT_REQ = 1` (FPGA переконфигурировали или сбросили),
AVR начинает с шага 1.

### 5.2 Главный цикл

- `MATRIX`, `CTRL`, `JOY` — при изменении и, для надёжности, повтор раз в 100 мс.
- `MOUSE` — на каждый отчёт мыши.
- `RTC SET 00` с регистрами времени (0..9) раз в 500 мс, как сейчас.
- OSD — пакетами `WRITE` по строкам или прогонам знакомест (раздел 5.3).
- Если за проход не ушло ни одного пакета, `SYS POLL`.
- Статус каждого пакета разбирается: LED, `RTC_PEND` → `RTC GET`, пока бит не снимется (по одной
  записи на пакет, каждую в `rtc_set_data`), `INIT_REQ` → старт заново.

### 5.3 OSD

`osd_set_pos()` закрывает открытый пакет `WRITE` (CS вверх) и запоминает адрес. Первый
`osd_write()` после этого открывает новый пакет (CS вниз, `02 01`, адрес) и пишет знакоместо,
следующие подряд — по 2 байта в тот же пакет. Пакет закрывается перед любым другим пакетом и в
конце прохода цикла. Буфер в RAM не нужен.

## 6. Сторона FPGA

- `rtl/avr/avr.vhd`: те же порты в сторону ядра (`KB`, `SOFT_SW`, `RESET`, `TURBO`, `MAGICK`,
  `WAIT_CPU`, `KB_MODE`, `JOY_*`, `OSD_*`, `SCREEN_MODE`, `DIVMMC_EN`, `NEMOIDE_EN`, `PLUS3E`,
  мышь, RTC RAM, `JOY`); `KB_SCANCODE` и `LOADED` уходят. Порт `OSD_COMMAND` заменяется шиной
  записи видеопамяти OSD (адрес, данные, строб) — правка `overlay.vhd`.
- Транспорт по образцу `kg_l2_link.v` (karabas-go-modules), переписанный на VHDL: сдвиговый
  регистр на `AVR_SCK`, байт переходит в `clk_bus` через переключатель за 3 такта, ответ на
  позицию p грузится в сдвиговый регистр в конце байта p−1. Отличие: ответ на байт `T` — статус
  (у Go — 0).
- Конец пакета — CS в 1 дольше нескольких тактов `clk_bus` (у Go 8 тактов: 0,33 мкс при
  24 МГц; отсюда 1 мкс в разделе 1).
- Уходят: `spi_slave` (24 бита), очередь `queue` (dcfifo 512 × 24), автомат `qstate`, пакеты LED.
  Приходят: транспорт, декодер целей, FIFO RTC (256 × 16 в M9K). На EP4CE6 блок должен стать
  меньше 550 LE (сейчас, по отчёту фиттера CI).
- SDC: `AVR_SCK` объявлен на 8 МГц, чтобы тайминги проверялись с запасом для любой частоты.

## 7. Сравнение с v1

| | v1 | v2 |
|---|---|---|
| Холостой проход цикла | 10 кадров клавиатуры + кадр джойстика, 33 байта | `SYS POLL`, 2 байта |
| Нажатие клавиши | 10 кадров, 30 байт (каждый проход) | `MATRIX`, 8 байт (при изменении) |
| Переключатель | в тех же 10 кадрах | `CTRL`, 6 байт |
| Знакоместо OSD | 4 кадра, 12 байт | 2 байта в пакете `WRITE` |
| Весь экран OSD | 832 × 12 ≈ 10 КБ | около 1,7 КБ (по пакету на строку) |
| Старт | `INIT` с опросом NOP, 8 кадров номера сборки, 2 × 256 кадров RTC | `STATUS` 15 байт, `RTC SET` 259 байт |
| LED | кадры в очереди, заполняют её наполовину | биты статуса |
| Запись CPU в RTC | кадр в общей очереди за кадрами LED | FIFO RTC, бит статуса |
